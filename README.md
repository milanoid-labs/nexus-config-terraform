# Nexus configuration (OpenTofu)

OpenTofu configuration for the homelab Nexus Repository (Community Edition, LXC 203 on
Proxmox, `http://192.168.1.204:8081`): repositories, roles and service users.

Nexus itself (the LXC and its docker-compose) is set up by hand; this repo only manages
what lives *inside* Nexus. Anything not declared here (for example the repositories
Renovate already uses) is left alone.

## Layout

| File | Manages |
|---|---|
| `docker.tf` | `docker-hosted`: a hosted Docker/OCI registry with path-based routing, so images are `192.168.1.204:8081/docker-hosted/<image>:<tag>` on the normal port. Tags are immutable (`ALLOW_ONCE`). |
| `security.tf` | `docker-hosted-pull` / `docker-hosted-push` roles and the service users `ci-push` and `k8s-pull`, with generated passwords |
| `realms.tf` | The **complete** list of active security realms: Local Authenticating + Docker Bearer Token (needed by Docker/Podman clients, see the comment there). Removing a realm here switches it off. |
| `terraform.tf` | Backend, providers, the Nexus connection variables |

State lives in S3 (`milanoid-labs-terraform-tofu-state`, key
`nexus-config-terraform/terraform.tfstate`). CI's AWS roles for it are managed centrally
in `milanoid-labs-terraform/bootstrap/aws-oidc/tofu_repos.tf`.

## Credentials

OpenTofu logs in as the Nexus user `tofu` (role `nx-admin`). It was created by hand once
(bootstrap: tofu can't create the account it logs in with); the built-in `admin` stays
personal.

- CI: repo secrets `TF_VAR_NEXUS_USERNAME` / `TF_VAR_NEXUS_PASSWORD`.
- Locally: `source ~/.config/nexus-config-terraform.env` (mode 600; sets the two
  `TF_VAR_nexus_*` variables and `AWS_PROFILE=milanoid`).

Service user passwords are generated by `random_password` and exist only in state:

```sh
tofu output -raw ci_push_password    # -> kubevirt-scaleset repo secret
tofu output -raw k8s_pull_password   # -> /etc/rancher/k3s/registries.yaml on kubevirt01
```

Rotate one with `tofu apply -replace=random_password.<name>`, then update its consumer.

## Workflow

PR → `Tofu Plan` posts the plan as a PR comment → merge → `Tofu Apply` on `main`.
`main` is protected by a ruleset (PR required), managed in `milanoid-labs-terraform`.

CI runs on `homelab-runners`: Nexus is only reachable on the LAN, so GitHub-hosted runners
can't plan or apply this repo. Nexus is plain HTTP, so the `tofu` credentials cross the
LAN unencrypted.

## Using docker-hosted

```sh
# Docker/containerd must treat the registry as insecure (HTTP), e.g. Docker daemon.json:
#   "insecure-registries": ["192.168.1.204:8081"]
docker login 192.168.1.204:8081 -u ci-push
docker push 192.168.1.204:8081/docker-hosted/<image>:<tag>
```
